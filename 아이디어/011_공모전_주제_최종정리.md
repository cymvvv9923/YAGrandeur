## 3. 상위 후보 비교

### 1. 공기 계기판 — "차에 없던 계기판 하나"
- **왜 1순위**: 네 기준 모두 ◎, 서버 없이 차 한 대로 완결, Virtual Console로 탑승·내기순환을 바꾸며 바로 시연
- **사업성**: 모든 운전자·매 주행 자동 작동 → MAU가 차량 수에 비례. 제어 SDK가 열리면 자동 외기 전환으로 확대
- **보완**: CO₂ 추정 모델의 근거(인원당 배출량, 실내 부피, 환기율) 제시. 탑승 값이 반대로 들어오는 점 처리

### 2. 차 안 쉼 — "차를 가장 안전한 낮잠 공간으로"
- **왜**: 007에서 유일하게 전부 ◎. 직장인·기사·학부모가 매일 하는 행동이라 리텐션이 자연스러움
- **보완**: 공기 계기판의 CO₂ 추정을 "쉬는 동안 환기 점검"으로 넣으면 두 주제가 하나로 강해짐

### 3. 다 같이 데려다주기 — "마지막 사람이 내릴 때까지"
- **왜**: 핵심 기능이 에뮬레이터에서 실제로 동작함을 확인한 유일한 주제. v3.0.5 신규 경유지 API를 정면으로 씀
- **제약**: 경유지 최대 2개 → 한 번에 3명까지, 4명 이상은 다시 요청
- **보완**: 내비 지도가 에뮬레이터에서 비어 있어 시연은 앱 화면·폰 화면 중심

### 4. 차들이 함께 만드는 도로 정보 — "차가 늘수록 정확해지는 지도"
- **왜**: 현대차 PM에게 가장 매력적인 플랫폼형. Pleos 차량이 늘수록 가치가 커짐
- **부담**: 서버 집계 + 여러 대 차량 데이터를 가짜로 만들어야 시연 가능. 위치 동의·익명화 설계 필요

### 5. 들를 곳 / 출발 비서 — "할 일과 경로를 잇는다"
- **왜**: 사용자층이 가장 넓고 시연이 쉬움. 경유지 API 동작 확인
- **약점**: 휴대폰 위치 리마인더와의 차이(경로에 바로 넣기, 도착 시 자동 완료)를 분명히 해야 함

## 4. 묶으면 더 강해지는 조합

| 묶음 | 구성 | 효과 |
|---|---|---|
| **차 안 공기·휴식** | 공기 계기판 + 차 안 쉼 | 주행 중엔 공기, 정차 중엔 휴식. 모든 기준 ◎, 시연 쉬움 |
| **태우고 내려주기** | 다 같이 데려다주기 + 픽업 라이브(008) + 우리집 차 같이 쓰기 | 가족·모임 이동 플랫폼. 사업성 최상, 짝 앱 필요 |
| **동승자가 편한 차** | 체감 리포트 + 멀미 케어 + 조수석 낮잠 | 동승자 관점의 새 메시지, 그랜저 가족차 이미지와 연결 |
| **차들이 만드는 지도** | 레인맵 + 숨은 위험 지도 | 플랫폼형, PM 매력 최상, 구현 부담 큼 |
| **출발 비서** | 들를 곳 + 주유 타이밍 + 장거리 점검 + 경고등 | 매일 여는 앱, 대표 기능을 하나로 좁혀야 함 |

## 6. 확정 전에 남은 확인 (에뮬레이터)
- 내기순환·풍량·창문 이벤트를 앱에서 받는지 → 공기 계기판, 차 안 쉼
- 시트 등받이 각도·위치 이벤트 → 차 안 쉼, 바디케어
- 연료량·경고등 → 주유 타이밍, 카히스토리
- 앱이 백그라운드이거나 시동을 끈 뒤에도 데이터를 받는지 → 차 안 쉼, 카히스토리
- 글레오 연동 동작 여부 → 출발 비서, 음성 메모
