## 1. 핵심 요약: 기획 전에 꼭 알아야 할 7가지

1. **플랫폼은 Android Automotive OS(AAOS) 기반 Pleos Connect.** 일반 Android 앱 개발과 거의 같고(Kotlin/Java), 차량 데이터는 Pleos Connect SDK로 접근.
2. **SDK 제공 상태 주의 ⚠️** — Playground "프로젝트 생성 및 SDK 사용 신청" 문서 기준(2026-10-27):
   - ✅ **바로 사용 가능 (신청 불필요)**: **Vehicle State(차량 상태 조회)**, **NaviHelper**
   - ⏳ **준비 중 (Coming Soon, 신청 불가)**: **FusedLocation, TextToSpeech, SpeechToText, Vehicle Control(차량 제어)**
   - 공모전 사이트는 5개 SDK 모두 사용 가능하다고 안내하지만, 실제 제공 상태는 문서에서 확인하라고 명시. → **10/28 설명회에서 질문 1순위.** 기획서는 5개 다 써도 되지만, 실제 구현은 Vehicle 조회 + NaviHelper 중심으로 계획하고 나머지는 대체 수단(Android 기본 TTS/STT 등) 플랜 B를 두는 것이 안전.
3. **TTS/STT는 클라이언트 ID·시크릿(서버 연결)이 필요** — Playground 프로젝트에서 발급.
4. **주행 중 제한이 강함** — Distraction Optimization(DO) 미선언 앱은 **주행 중 사용 불가**. 주행 중에는 키보드·동영상·설정·대용량 텍스트 금지(한국 등 "그 외 지역"도 동영상·설정·매뉴얼 제한). → "주행 중엔 음성/최소 UI, 정차 중엔 풍부한 UI" 구조가 심사의 "주행·정차 맥락"과 직결.
5. **화면 = Driving view(고정) + 앱 영역(최대 2개 창)** — 앱은 portrait(1창)/landscape(2창 확장) 둘 다 설계해야 함.
6. **에뮬레이터 + Virtual Console로 차량 상태(기어, 속도, 도어, 배터리, 공조, 경고등…)를 조작하며 시연 가능** — 실차 없이 2차 PT 시연 준비 가능.
7. **Gleo AI(42dot LLM 음성 비서)가 OS에 있음** — "Gleo Interface 구현 가이드"로 내 앱 기능을 Gleo 음성 명령에 연결 가능(차별화 포인트 후보, 제공 범위는 확인 필요).

## 3. Pleos 플랫폼 이해

| 용어 | 설명 |
|---|---|
| **Pleos** | 현대자동차그룹의 소프트웨어 중심 모빌리티(SDV) 브랜드 |
| **Pleos Connect** | AAOS 기반 차세대 인포테인먼트 플랫폼. 멀티 윈도우로 클러스터 정보(Driving view)와 앱을 동시에 사용 |
| **Gleo AI** | 42dot의 LLM 기반 개인형 모빌리티 AI 어시스턴트. 대화로 차량 기능 제어, **발화 좌석 인식**, proactive suggestion |
| **Pleos App Market** | 차량 특화 앱 마켓. 개발자가 직접 등록·심사·배포 |
| **Pleos Playground** | 개발자 포털 (문서, SDK, 에뮬레이터, 프로젝트 Workspace) |
| **Navigation** | 온라인 기반·차선 단위 내비게이션, Gleo와 연동한 음성 목적지 설정 |

- Pleos Playground: https://pleos.ai/playground
- Pleos Connect 소개: https://document.pleos.ai/docs/connect/guide/connect
- 용어집: https://document.pleos.ai/docs/connect/guide/glossary
- Playground Workspace(내 프로젝트): https://pleos.ai/playground/console/projects
- App Market Console: https://appmarket.pleos.ai/console/

### Pleos Playground 개발 흐름 (공식 6단계)
① 앱 개발 시작하기 → ② 개발 환경 구성 → ③ 앱 기획·설계 → ④ 앱 개발 → ⑤ 앱 테스트 → ⑥ 앱 등록

### SDK API 정책 (기획 시 참고)
- **AAOS Alignment**: AAOS 표준 API에 같은 기능이 있으면 표준 API 사용 권장, SDK는 중복 제공 안 함
  - 표준 데이터(속도, 기어 상태, 외기 온도, 연료 레벨 등) → **AAOS Car API** (`CarPropertyManager`)
  - 특화 기능(제조사 전용 시트 제어, 특화 라이팅, 보안 인증 등) → **Pleos Connect SDK**
- 차량 모델마다 지원 API가 다름 → 모델명 분기 금지, **`checkXXXCapabilities` / `isSupported()`로 런타임 확인**
- 퍼미션은 **Pleos App Market과 사전 협의·승인된 범위**만 사용 가능 (미승인 퍼미션 선언 시 앱 심사 탈락)

| SDK | 차량 모델별 호환성 |
|---|---|
| Vehicle SDK | 모델에 따라 다름 (capability API로 확인) |
| NaviHelper SDK | 내비게이션 탑재 차량은 전체 호환 |
| TextToSpeech / SpeechToText | 전체 호환 |
| FusedLocation SDK | 모델에 따라 다름 (`isSupported`로 확인) |

### 4-2. Vehicle SDK — 차량 상태 조회 / 제어
문서: https://document.pleos.ai/docs/pleos-only/connect-sdk-pleos/Vehicle/intro

- 진입점 `Vehicle(context)` → `initialize()` → `getDoor()`, `getHvac()` 등 **도메인 객체** 획득 → `check*Capabilities` / `get*` / `set*` / `register*`(콜백) → `release()`
- 모든 결과는 IPC 비동기 `onComplete` / `onFailed` 람다로 전달

| 도메인 | 내용 | 조회 퍼미션 |
|---|---|---|
| Brake | 브레이크 페달, 주차 브레이크 | CAR_DRIVE |
| CarInfo | 차량 크기·제조사·연식, **VIN** | CAR_INFO |
| Display | 표시 단위(온도 단위 등) | CAR_INFO |
| Door | 도어 열림/닫힘·잠금 | CAR_DOORS |
| DrivingMode | 드라이브 모드, **크루즈 컨트롤** | CAR_DRIVE |
| EvBattery | **EV 배터리·충전 상태·전비** | CAR_ENERGY |
| Fuel | 연비·연료량 | CAR_ENERGY |
| HVAC | 온도·풍량·습도 등 공조 | CAR_CLIMATE |
| Light | 조명 상태, **앰비언트 라이트** | CAR_LIGHTS |
| Odometer | 총 주행거리, **트립 거리/시간** | CAR_DRIVE |
| Safety | 차량 경고(Warning), 경고등(Telltale) | CAR_SAFETY |
| Seat | 좌석 위치·각도·기능, 탑승 감지 | CAR_SEATS |
| SideMirror | 사이드미러 열선 | CAR_MIRRORS |
| Steeringwheel | 핸들 상태·열선 | (문서 참고) |
| Tire | 타이어 상태(공기압 저하) | CAR_SAFETY |
| Toll | 하이패스(ETCS) 음성 안내 음량 | CAR_TOLL |
| TurnSignal | 방향지시등 | CAR_LIGHTS |
| Window | 창문 제어·상태 | CAR_WINDOWS |
| Wiper | 와이퍼 | CAR_WINDOWS |

- 퍼미션 형식: 조회 `pleos.car.permission.CAR_*`, 제어 `pleos.car.permission.CONTROL_CAR_*`
- v2.3.2 신규: `getVINInfo`, `getCurrentEvEfficiency`, `registerEvBatteryStateOfCharge`, Smart Glass level, `TripStatistics`, `TelltaleData` 모델 등
- v2.3.2 삭제: `VehicleSpeedListener` → **차량 속도는 AAOS `CarPropertyManager` (`PERF_VEHICLE_SPEED`)로**
- 관련 문서: [Capability 확인](https://document.pleos.ai/docs/pleos-only/connect-sdk-pleos/Vehicle/check-capability) · [Get](https://document.pleos.ai/docs/pleos-only/connect-sdk-pleos/Vehicle/get-property) · [Set](https://document.pleos.ai/docs/pleos-only/connect-sdk-pleos/Vehicle/set-property) · [Callback](https://document.pleos.ai/docs/pleos-only/connect-sdk-pleos/Vehicle/callback) · [Permission](https://document.pleos.ai/docs/pleos-only/connect-sdk-pleos/Vehicle/vehicle-permission) · [Error code](https://document.pleos.ai/docs/pleos-only/connect-sdk-pleos/Vehicle/vehicle-error-code)

```kotlin
// 공식 Getting Started 예제 (도어 위치 조회)
val vehicle = Vehicle(context)
vehicle.initialize()
val door = vehicle.getDoor()
door.getCurrentDoorPosition(
    area = DoorArea(DoorValue.ROW_1_LEFT),
    onComplete = { pos: Int? -> /* 사용 */ },
    onFailed = { e: Exception -> /* 에러 처리 */ }
)
// release()는 onDestroy 등에서
```

### 4-3. NaviHelper SDK — 내장 내비게이션 연동
문서: https://document.pleos.ai/docs/pleos-only/connect-sdk-pleos/NaviHelper/intro

- 목적지 설정·확인·취소 / 경로 옵션 변경·재탐색 / 경유지 추가·조회·제거
- `requestRouteWithWaypoints`, `requestTrip`, `requestNavigationScreen` (v3.0.5 신규)
- 이벤트: `onNavigationStatus`, `onRoutingCompleted`, `onTripInfo`, **`onCautionPointInfo`(단속카메라 등 주의 지점)**
- 데이터: 북마크(집/회사/**EV 충전소**), 최근 목적지, 남은 거리·시간, POI provider, 교통 정보
- 흐름: `NaviHelper` 생성 → `initialize(onConnected, onFailed)` → `addListener()` → API 호출 → `removeListener()` / `release()`
- ⚠️ v3.0.5에서 좌표 인자 순서가 **(latitude, longitude)**로 변경됨
- 관련: [목적지](https://document.pleos.ai/docs/pleos-only/connect-sdk-pleos/NaviHelper/destinations) · [경로](https://document.pleos.ai/docs/pleos-only/connect-sdk-pleos/NaviHelper/routes) · [경유지](https://document.pleos.ai/docs/pleos-only/connect-sdk-pleos/NaviHelper/waypoint-settings) · [이벤트](https://document.pleos.ai/docs/pleos-only/connect-sdk-pleos/NaviHelper/event-listeners)

### 4-4. FusedLocation SDK — 차량 위치 ⏳(준비 중)
문서: https://document.pleos.ai/docs/pleos-only/connect-sdk-pleos/FusedLocation/intro

- `getLastKnownLocation()`, `registerFusedLocationCallback()`, `isSupported()`, `showLocationAccessBlockedPopup()`
- **`addProximityAlert()` / `removeProximityAlert()`** — 지정 영역 진입/이탈 알림(지오펜스) ← 픽업·주차·도착 기반 서비스에 유용
- `LocationData`: 위도, 경도, 고도, 진행 방향, 신뢰도, 타임스탬프
- 퍼미션: `pleos.car.permission.FUSED_LOCATION`

### 4-5. TextToSpeech / SpeechToText — 음성 입출력 ⏳(준비 중)

## 5. 개발 환경 세팅 가이드

| 항목 | 요구사항 |

| 샘플 앱 기준 | JDK 17, AGP 8.8.2, Gradle wrapper 8.10.2, Kotlin 2.0.0, compile/targetSdk 35 |

### 순서
1. **Playground 가입 → 프로젝트 생성 → SDK 사용 신청**
   https://document.pleos.ai/docs/pleos-only/create-my-project
   - 프로젝트 ID(Key): App Market 심사 시 필요 / 클라이언트 ID·시크릿: TTS·STT용
2. **에뮬레이터 설치** — Android Studio → Tools > SDK Manager > SDK Update Sites > `+`
   - Name: `Pleos Connect System Image`
   - URL (Windows/Linux): `https://nexus-playground.pleos.ai/repository/raw-releases/connect-avd/2.x/crp-sys-img.xml`
   - URL (Mac): `https://nexus-playground.pleos.ai/repository/raw-releases/connect-avd/2.x/crp-arm64-sys-img.xml`
   - SDK Platforms → API 34 → Pleos Connect System Image 체크 → 설치 → Android Studio 재시작
3. **AVD 생성** — Device Manager > Create device > **Automotive** > Pleos Connect v2.1.0 → Advanced: **Cold boot**, **RAM 4GB** → API 34 Pleos Connect v2.1.0 APIs
4. **프로젝트 생성** — New Project > Automotive/Car > Empty Activity, Kotlin, minSdk 28
5. **Maven 저장소 + 의존성 추가** → **매니페스트 퍼미션 선언** → 첫 API 호출
   - 빠른 시작: https://document.pleos.ai/docs/pleos-only/getting-started
   - 에뮬레이터 설치 상세: https://document.pleos.ai/docs/connect/guide/getting-started/application-development/setup-connect-sdk-emulator

## 6. 에뮬레이터 & Virtual Console (시연·테스트)

에뮬레이터에서 차량 상태를 웹 콘솔로 조작 → **실차 없이 시나리오 시연 가능 (2차 PT·영상 제작에 핵심)**

```bash
adb forward tcp:8088 tcp:8088
# 브라우저에서 http://127.0.0.1:8088/
```

| Domain | 조작 가능 항목 |
|---|---|
| Vehicle | 차량 알림 표시/숨김 |
| Motion | **기어(P/R/N/D)**, 브레이크 페달(0~100%), 주행거리, 스티어링 각도(-540~540°), 핸들 열선 |
| ADAS | 크루즈 상태(Not ready~Full autonomous), 목표 속도 |
| Convenience | 도어·잠금·트렁크/프렁크, 실내등·독서등, **앰비언트 밝기/색상**, 외부등·상향등·비상등·제동등, 방향지시등, 창문 위치/잠금, **좌석 탑승 감지(Seat Occupancy)**, 와이퍼, 글로브박스, **하이패스 시나리오(요금소 진입/진출)** |
| Safety | 경고등(주차 브레이크, 안전벨트, ABS, **TPMS** 등) Off/On/Blink |
| Energy | 주행가능거리, 배터리 에너지/SOC/용량, 충전 전류·목표 충전량, 충전 스위치·포트 |
| Climate | 공조 전원, A/C, Auto, Dual, 내외기, 풍량, 풍향, 제상, 목표 온도, 시트 열선/통풍, 공기청정 |

## 7. 차량용 앱 설계 제약 (UX·주행 규제)

> 심사 항목 "차량특화성(주행·정차 맥락)"과 직결. 기획서에 **주행 중 / 정차 중 동작 차이**를 명시하면 이해도가 드러남.

### 7-1. 화면 구조
- **Driving view**(운전자 쪽 고정 영역, 앱이 가릴 수 없음) + **앱 영역 최대 2창**
- **portrait** = 1창(핵심 기능), **landscape** = 2창 확장(부가 정보) → 둘 다 설계
- 앱은 자주 포그라운드/백그라운드 전환됨 → 상태 복원, 백그라운드 리소스 최소화
- 문서: https://document.pleos.ai/docs/pleos-only/vehicle-app-planning-guide/app-structure-screen-model

### 7-2. 주행 규제 (CarUxRestrictions)
- DO(Distraction Optimization) **미선언 앱: 주차 중 사용 가능 / 주행 중 사용 불가**
- 주행 중 기능 제한 (한국 등 "그 외 지역" 기준):

| 기능 | 주행 중 |
|---|---|
| 키보드 · 다이얼패드 · 검색 | ✅ (북미는 ⛔, 검색은 음성만) |
| 미디어 앱 로그인·설정·검색 | ✅ |
| 디지털키·도어·시트·차량 설정 | ⛔ |
| **동영상 시청** | ⛔ |
| 내비 검색 | ✅ |
| QR 로그인 | ⛔ |
| 매뉴얼(대용량 텍스트) | ⛔ |

- 문서: [주행 규제 정책](https://document.pleos.ai/docs/pleos-only/vehicle-app-planning-guide/driving-restiction-policy) · [주행 규제 개발 가이드](https://document.pleos.ai/docs/pleos-only/vehicle-app-developer-guide/driving-restriction-development-guide)

### 7-3. 앱 카테고리 (주행 중 허용 범위가 다름)
Maps/Navigation · Mobility Services · Lifestyle · Entertainment · Business · Music/Audio · Kids · Social/Communication
- 주행 중 제한적 허용: **Music/Audio**(단순 조작), **Maps/Navigation**(경로 안내·TBT 음성), **Mobility Services**(차량 관리, 현재 위치 기반 정보, EV 충전소·주유소·주차장 찾기)
- 문서: https://document.pleos.ai/docs/pleos-only/vehicle-app-planning-guide/app-category

### 7-4. 운전자 주의 분산 방지 UX 원칙
- 짧은 시간에 이해되는 간결한 정보, 주행 중 동영상·애니메이션 최소화
- 최소 조작으로 도달하는 단순한 메뉴, 자주 쓰는 기능은 첫 화면·상단
- 큰 터치 영역, 높은 대비, 텍스트 최소화 / **음성·물리 버튼(CCP 조그 다이얼) 연계**
- 텍스트 입력보다 **프리셋·최근 항목·음성 입력** 우선
- 게임·웹서핑·피트니스 등 주의 분산 활동 유도 금지
- 오디오는 오디오 포커스 정책 준수
- 문서: https://document.pleos.ai/docs/pleos-only/vehicle-app-planning-guide/driver-distraction-guideline
- 운전용 앱 디자인: https://document.pleos.ai/docs/connect/guide/docs-design/Introduction/designing-apps-for-driving
