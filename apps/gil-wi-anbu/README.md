# 길 위의 안부 (가칭)

기획: [`../../원우_최종.md`](../../원우_최종.md)

서클(가족) 구성원이 폰 웹에서 **장소에 메시지**를 남기면, 서클의 누군가 차로 그 근처를 지나고 **정차(기어 P)** 했을 때 차에서 들려줍니다. 하루 운전 기록으로 **차의 일기**를 쓰고, 본인이 허락한 항목만 서클에 보입니다.

## 구성

| 폴더 | 내용 |
| :-- | :-- |
| `car-app/` | 차량 앱 (Kotlin, Vehicle SDK 2.3.2 + NaviHelper 3.0.5) |
| `server/` | Node 서버, 의존성 없음 (`node server.js`, 포트 8090). 데이터는 `server/data/db.json` |
| `web/` | 폰 웹 (서버가 `/`에서 제공). 지도에서 장소 고르기, 녹음/글, 소식, 내 메시지 |
| `demo.ps1` | 시연 시나리오 자동 실행 |

### 차량 앱 코드

| 파일 | 하는 일 |
| :-- | :-- |
| `MainActivity.kt` | 화면만 맡음: 홈(일기 크게)·운전자 선택·재생·일기·공유 설정·사용자 관리·메시지 남기기·서클 소식, 뒤로/홈 |
| `Engine.kt` | 앱의 두뇌: 기어·위치 받기, 근처 계산, 대기열, 재생 흐름, 서버 새로 고침 |
| `AnbuService.kt` | Engine을 살려 두는 포그라운드 서비스, 알림 버튼 처리, 부팅 때 자동 시작 |
| `Notifier.kt` | 상태 알림, 운전 중 도착 알림, 정차 중 재생 알림(들었어요·다시 듣기·나중에), 앱 앞으로 띄우기 |
| `Recorder.kt` | 차에서 목소리 녹음 (m4a, 60초까지) |
| `Dictation.kt` | 말하면 글로 적기 (안드로이드 기본 음성 인식, ko-KR). 인식 서비스가 5초 안에 응답이 없으면 그만두고 알림 |
| `CarSignals.kt` | 기어(P 여부), 누적 주행거리, 내비 현재 위치(3초마다), 와이퍼·하향등·조수석 탑승·운전석 문, 경유지 넣기 |

| `TripStore.kt` | 오늘 기록(거리·쉬어간 횟수·들은 메시지)과 설정, 일기 문장 |
| `Api.kt` | 서버 통신 (현재 위치는 보내지 않음) |

## 운전 중에는 어떻게 도나

운전할 때는 내비가 화면에 떠 있고, 이 앱은 뒤에서 돕니다 (`AnbuService` + `Engine`).

| 상황 | 화면 | 앱이 하는 일 |
| :-- | :-- | :-- |
| 시동 후 정차(P) | 앱 (운전자를 안 골랐으면 알림 → 눌러서 고르기) | 운전자 고르기, 설정·입력 |
| 운전 중 | 내비 | 근처 메시지를 조용히 모음. 지나는 순간 알림 소리 한 번 + "차를 세우면 들려드릴게요" |
| 다시 정차(P) | Pleos가 마지막 앱(이 앱)을 다시 보여 줌 + 재생 알림 | "지나온 길에 메시지가 N개 있어요" → 재생 → **끝까지 들으면 5초 뒤(글은 10초 뒤) 「들었어요」 자동 전송** |
| 출발(D·R·N) | **항상 기본 내비로 바뀜** | 재생 중이던 건 대기열로. 카운트다운 중에 출발하면 들은 것으로 보고 전송 |
| 앱 화면이 없어도 | 알림 | 알림의 「들었어요」「보내지 않기/다시 듣기」「나중에」 버튼 |

- 운전자가 버튼을 누르지 않아도 되게 「들었어요」는 자동입니다. 보내기 싫으면 「보내지 않기」, 끄려면 공유 설정의 "끝까지 들으면 버튼 없이 「들었어요」 보내기".
- 앱이 스스로 앞으로 나오는 건 안드로이드가 막습니다(로그: `Background activity launch blocked`). P에서 앱이 보이는 건 Pleos가 마지막 앱을 다시 보여 주기 때문이고, 출발 때 내비로 바꾸는 건 앱이 보이는 동안이라 됩니다.

- 기본은 **정차했을 때 재생**합니다 (기획서 4장). 운전 중 바로 재생이 허용되는지는 공모전 문의 사항입니다.
- 입력(메시지 남기기·설정·사용자 관리)은 **정차 중 차 화면** 또는 **폰 웹**에서만 합니다. 운전 중엔 조작 화면이 닫힙니다.
- 설정 화면에 있는 동안은 자동 재생을 미루고, 홈으로 돌아오면 재생합니다.

### 기어별 동작

| 기어 | 앱 화면 | 재생 | 기타 |
| :-- | :-- | :-- | :-- |
| 모름 (시동 직후) | 조작 버튼 숨김 | 안 함 | "차 상태를 확인하는 중" |
| P | 설정·입력 가능 | 대기 메시지 재생 → 자동 「들었어요」 | D로 달린 뒤의 P만 "쉬어간 횟수"로 셈 |
| D | 기본 내비로 전환, 열린 입력 창 닫음 | 멈추고 대기열로 | 근처 통과 시 알림 한 줄 |
| R | 조작 버튼 숨김, **내비를 띄우지 않음** (후방 카메라를 가리지 않게) | 멈추고 대기열로 | P→R→P 주차 조작은 쉬어간 횟수로 안 셈 |
| N | 조작 버튼 숨김 | 멈추고 대기열로 | |

- 같은 기어 값이 여러 번 와도 한 번만 처리합니다.
- 받은 메시지는 기기에 저장해 두므로, 앱이 꺼졌다 켜져도 그날 안에는 다시 들려줍니다.

## 메시지가 열리는 조건

메시지를 남길 때(폰 웹·차 화면) "언제 들려줄까요?"를 고릅니다. 판단은 모두 차 안에서 하고, 차 상태는 서버로 보내지 않습니다.

| 조건 | 차 신호 | 열리는 때 | 재생 |
| :-- | :-- | :-- | :-- |
| 이 장소를 지나면 | 내비 현재 위치 | 반경 안에 들어올 때 | 다음 정차 때 |
| 비 오는 날 | 앞 와이퍼 켜짐 | 와이퍼가 움직일 때 | 다음 정차 때 |
| 밤길 | 하향등 켜짐 | 전조등을 켤 때 | 다음 정차 때 |
| 옆자리에 누가 탄 날 | 조수석 탑승 센서 | 조수석에 앉을 때 | 정차 중이면 바로 |
| 차에 탈 때 | 운전석 문 열림 | 문을 열 때 | 정차 중이라 바로 |

- 같은 메시지는 하루 한 번만 열립니다.
- 뒷좌석은 탑승 센서가 없는 차가 많아 보지 않습니다.
- 조수석 탑승 값은 에뮬레이터에서 **반대로** 들어옵니다(콘솔 Occupied → false, T01 기록과 같음). `CarSignals.OCCUPANCY_INVERTED`로 맞춰 두었고, 실차에서 방향이 맞게 들어오면 이 값만 `false`로 바꿉니다.
- 권한: `CAR_WINDOWS`(와이퍼), `CAR_LIGHTS`, `CAR_SEATS`, `CAR_DOORS`, `NAVI_ROUTE_SEARCH`(경유지). 없으면 `SecurityException ... need Permission`.

**일기**에도 들어갑니다: "비 오는 밤길을 달렸어요." "옆자리에 누가 함께 탔어요." (D로 달리는 동안의 상태만 셈)
비·밤길은 공유 설정에서 켜면 서클에 보이고, **동승 여부는 공유하지 않습니다.**

**들러 가기**: 장소 메시지를 들은 뒤 재생 화면이나 홈의 "📍 ○○ 들러 가기"를 누르면 내비 경유지로 들어갑니다(`NaviHelper.addWaypoint`, 내비 최대 2곳). 경로 안내 중일 때 의미가 있고, 에뮬레이터 내비는 요청을 받는 것(`OnAddWaypointRequest`)까지만 확인했습니다.

## 서클과 사용자

기본 서클은 **우리집(가족)** 하나이고, 구성원은 아버지 · 어머니 · 용민 · 형규 · 원우 · 미성 순서입니다 (`server/seed.json`).
차량 앱의 **사용자 관리** 화면에서 정차 중에 바꿀 수 있습니다.

- 서클 이름 바꾸기, 종류(가족/연인/친구) 바꾸기. 연인·친구로 바꾸면 일기 공유가 꺼집니다.
- 구성원 추가 · 이름 바꾸기 · 순서 바꾸기(▲▼) · 빼기. 빼면 그 사람이 남긴 메시지와 일기도 지워집니다.
- 이 순서가 "오늘 누가 운전하세요?" 화면과 폰 웹 목록에 그대로 쓰입니다.

## 왜 8090 포트인가

차량 앱과 폰 웹이 같이 쓰는 **우리 서버**의 주소입니다. 서클·메시지·「들었어요」·일기를 여기 저장해야 서로 다른 차와 폰이 같은 내용을 봅니다.

- PC에서 `node server/server.js`로 켜면 `http://localhost:8090`에서 열립니다. 폰 웹도 이 주소입니다.
- 에뮬레이터 안에서는 PC가 `10.0.2.2`로 보여서, 차량 앱은 `http://10.0.2.2:8090`으로 접속합니다 (`car-app/app/build.gradle.kts`의 `SERVER_URL`).
- 8088은 Virtual Console이 쓰고 있어서 겹치지 않게 8090을 골랐습니다. 숫자 자체에 의미는 없습니다.
- 제출할 때는 서버를 인터넷에 올리고 `SERVER_URL`을 그 주소로 바꿔야 합니다.

## 실행

```powershell
cd "D:\4.용아그(현대자동차)\apps"
.\_common\scripts\emulator.ps1
.\_common\scripts\console.ps1
Start-Process node -ArgumentList 'gil-wi-anbu\server\server.js'
.\_common\scripts\build-install.ps1 -App gil-wi-anbu -Run
.\gil-wi-anbu\demo.ps1 -Fresh       # 문 열고 탐 → 옆자리 탑승 → 출발 · 비 · 양재 사거리 통과 · 밤길 → 정차 → 재생 → 일기
.\gil-wi-anbu\demo.ps1 -Fresh -Shots .\shots   # 단계마다 화면 캡처
```

폰 웹: PC 브라우저에서 http://localhost:8090 (녹음은 localhost에서만 됨)

에뮬레이터에서 "달린 거리"가 0km로 나오는 이유: 에뮬레이터 차는 실제로 움직이지 않아서, 콘솔에서 속도를 올려도 누적 주행거리가 늘지 않고
내비 위치도 고정이다(`adb emu geo fix`도 내비가 따르지 않음). `demo.ps1`은 경로를 따라 콘솔 주행거리(`/vehicle/odometer`)를 올리고 위치를 보내서 거리를 만든다.

시연용 입력 (내비 위치를 에뮬레이터에서 못 바꿔서 만든 것):

```powershell
adb shell am broadcast -n ai.gilwi.anbu/.DemoReceiver --ef lat 37.4854 --ef lon 127.0364  # 위치 바꾸기 (화면을 띄우지 않음, 운전 중에 씀)
adb shell am broadcast -n ai.gilwi.anbu/.DemoReceiver --ez clear true                     # 실제 내비 위치로
adb shell am start -n ai.gilwi.anbu/.MainActivity --ef lat 37.4915 --ef lon 127.4870      # 위치 바꾸기 + 앱 화면 열기 (정차 중)
adb shell am start -n ai.gilwi.anbu/.MainActivity --es driver dad                      # 운전자 지정
```

### 11-03 버그 고침

| 버그 | 고친 것 | 확인 |
| :-- | :-- | :-- |
| 깨진 주소(`/%E0%A4%A`) 한 번에 서버가 꺼짐 | 주소 해석을 오류 처리 안으로, 400으로 답함 | ✅ 400 후에도 서버 살아 있음 |
| 일기 날짜에 HTML을 넣으면 폰 웹에서 실행될 수 있음 | 서버가 `YYYY-MM-DD`만 받음, 폰 웹도 날짜를 escape | ✅ 400 거절, 정상 날짜는 저장 |
| 「보내지 않기」 뒤 출발하면 정차할 때마다 다시 재생 | 「보내지 않기」한 메시지는 들은 것으로 쳐서 대기열에 다시 넣지 않음(알리지는 않음) | ✅ 출발·정차 두 번, 다시 안 나옴 |
| 대기열에 있던 메시지는 신고·삭제돼도 재생 | 서버 목록을 새로 받을 때 없는 메시지는 대기열에서 뺌 | ✅ 운전 중 신고 → 정차 때 재생 안 함 |
| 알림 카운트다운 숫자가 화면과 어긋남 | 알림에는 "잠시 뒤 「들었어요」를 보내요"로 숫자 없이 | ✅ |
| 서버가 wav를 `application/octet-stream`으로 보냄 | `audio/wav` 추가 | ✅ |
| 재생 화면을 1초마다 새로 그려 누르는 사이 버튼이 바뀜 | 카운트다운 중엔 상태 한 줄만 고침 | ✅ |
| 정차 직후 포커스가 주행 화면에 남아 **첫 터치가 버튼에 안 먹음** | 재생 화면이 보이는데 포커스가 없으면 앱이 스스로 앞으로 와서 포커스를 가져옴 | ✅ 한 번 탭으로 「보내지 않기」 |

- 정차했을 때 앱 화면이 다시 보일지는 Pleos가 정한다. 내비가 그대로 남아 있을 때가 있고, 그때는 알림 버튼으로 조작한다.
